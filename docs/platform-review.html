00

Summary

The platform works end to end, but authorization was the weak point: several privileged endpoints were reachable by any logged-in account, and the auth surface had no rate limiting. The three critical and four high-severity issues below are fixed in this pass; the medium and low items are documented with a fix and folded into the roadmap.

01

Security findings

Ordered by severity. "Risk" is what an attacker could do before the change; "Fix" is what was done or what to do.

Critical — fixed

C1 Broken access control on user management CriticalFixed
Where
Route::apiResource('users', …) sat under auth:sanctum only — no role gate.
Risk
Any logged-in client could list every user, and PUT /api/users/{id} accepted role_id — so a normal user could set their own account to admin, deactivate other admins, or delete accounts.
Fix
Deleted the open resource routes. All user management now lives at /api/admin/users behind role:admin,manager; role_id removed from UpdateUserRequest — role changes only through the dedicated admin-only assign-role endpoint.
Verified
client token → 403, no token → 401, admin token → 200, old route → 404.
C2 Full-database export open to any account CriticalFixed
Where
/api/reports/{properties,bookings,transactions} — Excel exports, auth:sanctum only.
Risk
Any logged-in user could download the entire bookings table (client names, phone numbers, viewing notes) and the transactions ledger (sale prices, commissions).
Fix
Moved to /api/admin/reports/* behind role:admin,manager. Verified client → 403.
C3 IDOR — read any booking by ID CriticalFixed
Where
BookingController@show($id) loaded a booking with no ownership check; the route is in the client group.
Risk
Incrementing the URL id exposed other customers' viewings — property, date, notes.
Fix
Added a check: a client sees only their own bookings, an agent only bookings for their properties, managers/admins see all — otherwise 404.

High — fixed

H1No rate limiting on authentication HighFixed
Risk
Login, register and password endpoints were unthrottled — open to brute force and credential stuffing.
Fix
Named limiters in AppServiceProvider: throttle:auth (5/min per email+IP, 20/min per IP) on login & register; throttle:otp (3/min, 10/hour) on the password endpoints; a global throttle:api (90/min) on every route. Verified: 429 after 5 bad logins.
H2Weak password-reset (OTP) flow HighFixed
Risk
6-digit code valid 60 min, stored in plaintext, unlimited guesses; exists:users,email on "forgot" revealed which emails have accounts.
Fix
Code is hashed at rest, 10-minute TTL, 5-attempt lockout per email, and both endpoints return an identical generic message regardless of whether the account exists. Reset now enforces the same 8–15 / upper / number / symbol policy as registration.
H3Bearer tokens never expired HighFixed
Risk
sanctum.expiration = null — a leaked token worked forever.
Fix
7-day expiry via SANCTUM_EXPIRATION. Add sanctum:prune-expired to the scheduler (roadmap P1).
H4Debug mode leaks internals on error HighPartly
Risk
APP_DEBUG=true renders full stack traces — file paths, environment, DB credentials — on any unhandled error.
Fix
API errors are now forced to JSON (no HTML debug page). Still required for production: APP_DEBUG=false and APP_ENV=production on the live server (roadmap P4).

Medium — open

M1No authorization Policies — coarse role gate onlyMediumOpen
Risk
A manager can edit or delete any property and promote a user to admin; an agent can change the status of any booking. The role middleware gates the route, nothing gates the record.
Fix
Add PropertyPolicy, BookingPolicy, UserPolicy, TransactionPolicy and call $this->authorize() in every action. Rules: agents touch only their own listings/bookings; only admins grant admin/manager; nobody deletes or deactivates the last admin or themselves.
M2Mass assignment on PropertyMediumOpen
Risk
$fillable includes agent_id, is_featured, views_count — a manager can reassign any listing to any agent or feature anything via the API.
Fix
Set these explicitly in PropertyService, remove from $fillable / the FormRequest.
M3Public agent list over-sharesMediumOpen
Risk
GET /api/agents returns the full UserResource — email_verified_at, role object, raw timestamps — to anonymous visitors.
Fix
Add a slim PublicAgentResource (name, photo, title, public phone/email only).
M4Profile update has no step-up checksMediumOpen
Risk
A stolen token can change the account email (no re-verification) and password (no current-password check) — quietly locking the real owner out.
Fix
Require current password for password/email change; re-send verification and keep the old email active until confirmed.
M5No security headers / HTTPS enforcementMediumOpen
Fix
Add a middleware setting X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, and HSTS; URL::forceScheme('https') + TrustProxies in production.
M6Image uploads validated by extension onlyMediumOpen
Fix
mimes: is spoofable — add real content validation (Intervention/Image re-encode), randomised names (already done), and serve from a dedicated disk.
M7Unbounded query-driven cache keysMediumOpen
Where
PropertyController@index keys the cache on md5(json_encode($request->all())).
Fix
Whitelist the filter params before hashing; the service already trusts arbitrary input from $request->all() and should validate it.
M8Tokens in localStorageMediumOpen
Risk
Both SPAs keep the bearer token in localStorage — any XSS reads it. CORS runs with supports_credentials: true although cookies aren't used.
Fix
Either move to an httpOnly cookie + CSRF token, or accept the model and invest in XSS prevention (CSP, escaping, dependency audit). Turn off supports_credentials if staying on bearer tokens.
M9Swagger UI exposedMediumOpen
Fix
/api/documentation is public — gate it behind auth or disable l5-swagger in production.
M10No audit trailMediumOpen
Risk
Nothing records who deleted a listing, changed a price, or reassigned a role — you can't detect or investigate misuse.
Fix
spatie/laravel-activitylog on Property, User, Booking, Transaction + an admin audit-log screen. Log auth events (login, failed login, reset, role change) too.

Low — frontend hygiene

L1–L4Dashboard SPA hardeningLowOpen
L1
DefaultLayout guards on token presence only — no role check — and calls useEffect after a conditional return (hooks-order bug). Add a <RequireRole> wrapper.
L2
The router nests /bookings, /agents, /profile under GuestLayout — logged-in users get bounced away from them.
L3
axios-client sends Authorization: Bearer null when unauthenticated; skip the header instead. On 401 it clears the token but never redirects.
L4
The admin app ships a public /register — remove it; admins invite users.
02

Admin dashboard scope

Today the dashboard is a skeleton (Dashboard, Properties, Users, Bookings, Transactions, Agents, Profile) and the property form validates ~40 fields that don't exist in the database. Below is what each area needs to be usable, grouped by who sees it. recharts, react-dropzone, react-hook-form and DomPDF are already installed — the pieces are there, they need assembling.

Shell — every role

Access rework

  • Login + OTP reset only — no public registration
  • Role-aware sidebar and a route guard per page
  • Token auto-refresh, idle logout, "session expired" redirect
  • On 403 show a proper "not permitted" screen, not a blank page

Chrome partial

  • Breadcrumbs, page titles, toast notifications for every write
  • Notifications bell wired to /notifications
  • Dark mode, density toggle, saved table filters
  • Empty / loading / error states on every list

Admin & Manager

Overview build

  • KPI tiles — live listings, sold / rented this month, viewings this week, revenue MTD, active agents
  • Charts — bookings trend, sales by city, revenue by month
  • Recent activity feed (from the audit log)
  • Attention queue — pending viewings, unassigned enquiries, stale listings

Properties rebuild form

  • Table: filter by category, type, status, city, agent, price, featured; bulk feature / delete / restore
  • Editor matched to the real schema — title, description, type, category (the 6 typologies), status, price ₹, beds / baths / garages, area, address / city / state / PIN / lat-lng, features chips, featured flag, agent assignment
  • Image manager — drag-drop upload, reorder, set main, delete
  • Trash view with restore / permanent delete

Viewings build

  • Table + calendar view; filter by status, agent, date, property
  • Assign / reassign an agent, approve · decline · complete
  • Detail drawer with client info and an internal notes thread

Transactions build

  • Record a sale / rental — property, buyer, agent, amount, commission %, date
  • Generate an invoice PDF (DomPDF)
  • Earnings report, date-ranged, exportable

Users secure + build

  • Table: role, active, verified, search
  • Invite a user (email + role) rather than set a password directly
  • Activate / deactivate, assign role, soft-delete + restore
  • Guards: only admin grants admin/manager; can't lock out the last admin

Agents build API

  • Agent profile — specialisation, experience, bio, photo, public contact
  • Link to a user account; publish / unpublish on the public site
  • Performance — listings, closed deals, rating

Enquiries / Leads new

  • Inbox for the public Contact and Sell your property forms (which currently POST to a route that doesn't exist)
  • Assign, set status, convert to a viewing or a draft listing

Settings & Audit new

  • Public-site content the marketing app reads — company info, stats, office address, socials, featured-listings curation
  • Roles & permissions, email templates
  • Audit log — who changed / deleted what, when

Agent — scoped views

My work build API

  • Dashboard — my listings, my viewings, my earnings
  • My properties — only assigned; create is limited or needs manager approval
  • My viewings — accept / decline / complete, propose times
  • Commission statement, profile

Boundaries policy

  • Every agent view is filtered server-side to that agent — never client-side
  • No access to Users, Settings, other agents' data, or global reports

Roadmap

Phase 0 is done. The rest is ordered so the platform is safe to expose before it is feature-complete.

P0

Close the doors · done this pass

MySQL switch + seed · removed open user/report routes · role-gated admin API · auth & OTP rate limiting · hardened password reset · token expiry · booking IDOR fix · JSON API errors · wired featured / saved-properties / /auth/user · rebuilt route file · role test accounts.

P1

Lock the records · ~1–2 days

Policies for Property / Booking / User / Transaction · trim PropertyRequest to the real schema · implement the missing Property & Agent controller methods · PublicAgentResource · security-headers middleware · scheduled token & reset pruning.

P2

Make the admin usable · ~3–5 days

Role-guarded dashboard shell · property editor + image manager on the real schema · viewings workflow · users invite / roles · enquiries inbox + POST /api/contact.

P3

Operations · ~3–5 days

Transactions + invoice PDFs · reports & exports · agent-scoped views · audit log · settings (public-site content) · dashboard charts.

P4

Pre-launch · ~1–2 days

HTTPS + HSTS · APP_DEBUG=false · secrets rotation · gate or drop Swagger · rate-limit tuning · DB backups · a focused pen-test pass on auth and the admin API.
